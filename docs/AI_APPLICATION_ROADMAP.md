# AI 应用与后端项目改造计划

## 定位与边界

将现有家庭用药安全原型完善为“有证据约束的 AI 知识助手”。V1 的风险判断仍由版本化事实目录和 Safety Engine 决定；模型只参与受控工具选择和证据排序。V1 事实目录保存审定摘要、定位和链接；独立检索语料现有一个 FDA 来源章节快照。正式查询还未使用文档检索增强，因此不能称为文档 RAG，也不能把未审核的上传文档直接用于用药结论。

## 实施顺序与验收

1. **证据链产品化（本轮）**：正式查询响应附上命中事实对应的来源标题、发布方、版本和原始链接；前端可直接查看，且只展示已审查目录中的来源。无风险、范围外或知识不可用时不得出现凭空来源。API 契约和前端构建通过。
2. **来源文档检索（进行中）**：已完成已审事实摘要词法检索基线、本仓库自编项目文档的白名单与方法比较，并纳入一个经过来源和复用条件核对的 FDA 章节快照。该快照只供独立检索，未改变风险结论。现已将事实关联收紧到含审核锚句的片段，并加入单来源开发评测；“对乙酰氨基酚剂量”在两种方法下仍错排到重复成分片段，因此暂不允许检索片段辅助正式解释。医学结论始终由 Safety Engine 决定。

当前开发基线的运行记录见 [已审事实检索开发基线 v1](../reports/reviewed-fact-search-dev-v1.md)。它只用于回归，不能用于简历中宣称泛化检索准确率。
项目自编文档的对比记录见 [项目文档检索开发基线 v1](../reports/project-document-search-dev-v1.md)。
来源片段的开发评测见 [source-retrieval-dev-v2.md](../reports/source-retrieval-dev-v2.md)，不能用单来源结果宣称泛化检索准确率。
3. **AI 产品闭环（进行中）**：已加入不保存问题正文的结构化反馈和本地持久化，令牌 30 天后失效；页面可使用显式 session ID 完成受控代词追问，并展示上下文是否实际应用。本地反馈归因汇总已加入，下一步用独立评测验证检索和解释的版本变化；引入账户前先明确匿名会话边界。
4. **工程交付与评测**：固定独立测试集，对比无检索、检索、检索加校验的引用准确性、无依据陈述率、拒答和延迟；补端到端演示、配置与部署说明。只在真实测量后写入简历数字。

## 岗位展示

- AI 应用开发：知识构建、检索、受控工具、模型输出校验、评测。
- AI 全栈：上述链路及 React 引用交互、追问和反馈。
- Python 后端：API 契约、版本化数据、依赖降级、日志与测试。

每阶段以可演示的纵向链路为交付，不为关键词堆叠多智能体、MCP 或微调。完成阶段 2 前，简历只称“证据可追溯的受控 AI 工作流”，不称“RAG 系统”。
