# MedSafetyAssistant 安全边界

更新时间：2026-07-20

## 系统用途

本项目是家庭常见用药风险筛查的工程演示系统。它根据有限、版本化的事实目录识别重复成分、已收录禁忌和已收录相互作用，并用 LLM 将结构化证据组织为易读说明。

它不是医疗器械、医生、药师或处方系统，不能作为诊断、治疗、停药、换药或剂量调整的唯一依据。

## 允许系统做什么

- 从问题中识别候选药品和特殊状态；
- 查询已审核事实目录；
- 按确定性规则形成风险候选；
- 展示事实 ID、来源 ID、数据版本和限制；
- 在信息不足时追问；
- 在依赖不可用或超出覆盖范围时拒绝给出确定性结论；
- 让 LLM 在不新增医学事实的前提下解释证据。

## 禁止系统做什么

- 宣称某种组合“绝对安全”；
- 因为数据库没有记录就推断没有风险；
- 让 LLM 创建、修改或补全风险事实；
- 对剂量、疗程、处方调整给出个体化指令；
- 对急症、孕产妇、婴幼儿、严重肝肾疾病等高风险情况替代专业判断；
- 将未经核查的 legacy 数据描述为临床审核数据；
- 在响应或日志中泄漏密钥、traceback 或不必要的健康隐私信息。

## 结论状态

API 和界面必须使用以下状态之一，不能只返回自由文本：

| 状态 | 含义 | 用户表达要求 |
|---|---|---|
| `risk_found` | 在当前数据版本中命中一条或多条风险事实 | 展示风险、依据和求助建议 |
| `no_known_risk_in_scope` | 已识别实体，但当前审核范围内未命中风险 | 明确“不等于安全” |
| `insufficient_information` | 药名、剂型、状态或上下文不足 | 请求用户补充信息 |
| `out_of_scope` | 问题或实体不在 V1 支持范围 | 说明覆盖限制，不生成开放域答案 |
| `knowledge_unavailable` | 图谱或关键事实服务不可用 | 禁止显示“未发现风险” |

## 证据约束

- `risk_found` 必须至少包含一个 Evidence Fact；
- 每个 Evidence Fact 必须包含 `fact_id` 和至少一个 `source_id`；
- 生成回答中的风险事实必须能映射回 Evidence Fact；
- 非风险状态不得携带虚构风险事实；
- 来源或事实处于 `draft` 时，界面必须显示未审核状态，不能进入正式 V1 benchmark。

## 依赖故障策略

- Redis 故障：禁用历史记忆，当前问题仍可继续；
- Ollama 故障：保留结构化风险和证据，生成说明降级；
- Neo4j 故障：返回 `knowledge_unavailable`；
- 实体抽取不确定：返回 `insufficient_information`；
- 任何异常都不得转换成“无风险”。

## 紧急情况

界面应提示：如已出现呼吸困难、意识异常、严重过敏、持续呕吐、胸痛或其他急性症状，应立即联系当地急救服务或前往医疗机构，而不是继续等待系统回答。

该提示是风险沟通边界，不代表系统具备急症分诊能力。

## 数据与审核声明

项目当前数据尚未逐条完成来源定位，也没有具备资质的临床审核者签名。现阶段只能称为“legacy 工程演示数据”。完成来源对齐只证明记录与指定来源一致；只有具备资质的医生或药师才能完成临床审核。
