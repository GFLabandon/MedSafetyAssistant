# 匿名反馈归因与解释边界

正式查询成功且本地反馈库可用时生成随机 `feedback_id`。数据库只记录该令牌、结论状态、数据版本、实体解析状态、解释生成模式、回退原因、结构化会话是否应用、评价、固定原因类别及时间。问题正文、会话 ID、药名、账户和 IP 不进入反馈表。旧数据库启动时增量补列；旧记录的新字段保持 `null`。

本机运行：

```bash
python -m evaluation.feedback_report
# 或指定另一个本地数据库
python -m evaluation.feedback_report --db /path/to/feedback.sqlite3
```

报告只包含最近 30 天已登记查询数、已提交反馈数、评价与原因计数，以及按状态和版本分组的计数。不提供匿名反馈令牌或逐条导出。数据库不对外提供汇总 API；`FEEDBACK_DB_PATH` 可配置路径，默认文件被 Git 忽略。令牌 30 天后不可提交，过期行在后续查询时删除。

**如何使用：**先看需改进反馈集中在哪些状态、数据版本、生成模式或回退原因，再人工构造可公开的复现样例，加入独立测试集。没有反馈的查询和选择不反馈的用户也必须计入分母；自愿反馈存在选择偏差，不等于医学准确率、模型准确率或用户满意度。注册数只覆盖反馈库可用时的查询，不是全部 API 流量。当前没有真实用户验证数据，不据此写简历指标。
