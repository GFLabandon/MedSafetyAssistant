# 项目文档检索开发基线 v1

语料：`data/document_corpus_v1.json` 白名单中的 3 份本仓库自编文档，共 29 个确定性片段。每份文档的 SHA-256 在启动时校验；文件改动后需人工更新清单并重新评测。此语料解释项目实现，不是医学来源全文，也不参与风险结论。

运行 `python -m evaluation.project_document_search`，使用 `eval/project_document_search_dev_v1.jsonl` 中 4 条开发查询比较 top-1 文档 ID：词法重叠 3/4，本地哈希向量 4/4。词法失败样例“未知药品如何处理”排到了工具工作流文档；哈希向量在此小集合中排到输入解析文档。样例数量小，且属于开发集，不能推断一般检索质量或宣称模型语义理解。这里的哈希向量是词法特征，不是训练得到的 Embedding。

已验收：清单路径不能逃逸仓库、内容校验失败会拒绝启动、索引重建得到稳定 chunk ID、检索片段可通过独立 API 打开完整原文。下一步若要接入外部医疗来源，需单独审核使用许可、版本、摘录范围和事实对齐；不能直接将该语料或任意上传文本接入 Safety Engine。
