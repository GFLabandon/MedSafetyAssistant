# 来源片段检索开发评测 v3

运行：`conda run -n medsafety python -m evaluation.source_retrieval_contract --dataset eval/source_retrieval_dev_v3.jsonl --checksum eval/source_retrieval_dev_v3.sha256 --output reports/source-retrieval-dev-v3.json`。逐例结果、数据集与清单 SHA-256、目录版本和实现提交见 [JSON 报告](source-retrieval-dev-v3.json)。[v2 报告](source-retrieval-dev-v2.md)保留原始基线。

评测仅包含 **1 个 FDA 来源章节、3 个片段、14 个开发问题**；词法与本地哈希向量各运行一次，共 28 次。top-1 正确 **25/28**（词法 **14/14**，哈希向量 **11/14**）；预期事实关联正确 **27/28**；返回项的来源与事实 ID 越界 **0/28**。这里的事实关联仅指片段关联是否符合评测预期，不代表医学结论正确。

本轮在来源原文不变的前提下，为原文中确有的剂量说明与每日最大量句子添加中文检索锚词，将 `4,000` 与 `4000` 在索引中统一，并按目录中的药品实体限制明确提及其他药品的查询。新增的两条布洛芬负例均没有返回对乙酰氨基酚来源。主题限制只覆盖实体解析器能够识别的药品，不能保证所有未知药品查询都被排除。

**保留的失败：**哈希向量把两条中文剂量问题排到了每日最大量片段 `:003`，又把英文 `acetaminophen 4000 mg per day` 排到了重复产品片段 `:001`。后一条因此带出了该片段合法、但不符合该问题预期的重复成分事实 ID。哈希向量只是本地词法哈希特征，不是语义 Embedding；这些错排不能用来源关联合法来掩盖。

该数据集参与了规则调整，是开发集，不能当作独立泛化测试或临床准确率。来源片段检索仍是独立实验区，没有进入正式 Safety Engine 与风险解释链路。下一步应增加经过审核的不同药品来源和保留问题，再决定是否需要独立检索索引或语义模型。
